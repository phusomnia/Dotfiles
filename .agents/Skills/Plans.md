# Usage

Apply all referenced skills throughout the software development lifecycle.

## Implementation

Use `@Implementation.md` when:

* Designing solutions
* Writing new code
* Refactoring existing code
* Making architectural decisions

Focus on:

* Simplicity
* Maintainability
* Correctness
* Security
* Performance

## Code Review

Use `@CodeReview.md` when:

* Reviewing pull requests
* Evaluating design decisions
* Assessing maintainability
* Identifying defects and risks

Focus on:

* Correctness
* Architecture
* Security
* Reliability
* Knowledge sharing

## Documentation

Use `@Documentation.md` when:

* Creating technical documentation
* Writing API documentation
* Recording architecture decisions
* Explaining implementation details

Focus on:

* Clarity
* Accuracy
* Discoverability
* Long-term maintainability

## Testing

Use `@Testing.md` when:

* Designing test strategies
* Writing automated tests
* Validating quality
* Building CI/CD pipelines

Focus on:

* Confidence over coverage
* Behavior over implementation
* Fast feedback
* Reliable automation
* Risk-based testing

# Engineering Philosophy

Every change should be:

1. Correct
2. Tested
3. Reviewed
4. Documented

Code is not complete until all four disciplines have been applied.

# Definition of Done

A task is complete when:

* Requirements are implemented.
* Tests pass.
* Code review concerns are resolved.
* Documentation is updated.
* Quality standards defined by all referenced skills are satisfied.
